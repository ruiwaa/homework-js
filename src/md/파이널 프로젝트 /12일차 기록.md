### 💡 배운 점

- React Query를 사용하면 서버 데이터 캐싱과 상태 관리가 단순해짐
- UI 상태를 URL로 관리하면 새로고침 및 이동 시에도 상태 유지 가능
- DB 구조와 프론트 기준이 다르면 기능이 쉽게 깨지기 때문에 기준 통일이 중요
- 고정 데이터보다 DB 기반으로 UI를 생성하는 방식이 유지보수에 유리함

### 😵 어려웠던 점

- supabase를 폼에 연동하여 데이터를 보낼 때보다, 데이터를 가져오는 과정이 더욱 오래 걸렸다. 여러 DB타입을 같이 써야 되다보니 타입을 만들고 그걸 다시 슈파베이스에서 어떤 형태로 받아올지에 대한 문제를 고민할 필요가 있었다. DB가 들어가니깐 화면에 보여줄 형태로 만드는 부분이 이해되지 않았다. 지금 다음주 중반까지는 모든 페이지의 데이터를 연동하여 어느정도 완성을 해야 되기때문에, 천천히 이해할 여유가 없는 것 같다. 이러한 프로젝트를 2개 정도 더 하면 조금씩 감이 생기지 않을까? 라는 어찌보면 경솔할 수도 있는 생각이 들었다. 데이터를 불러오는 부분에서는 다음부터는 더미 데이터를 만들지 않고, 임의로 슈파베이스에 넣어 구현을 해보아야 할 것 같다. 아.. 그러긴에 로그인 페이지가 먼저 구현이 되어야 되니깐 슈파베이스에 있는 타입을 참고하여 더미를 만들 수 밖에 없을 것 같다.
