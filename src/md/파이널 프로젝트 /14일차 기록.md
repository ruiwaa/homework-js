### 💡 배운 점

- Supabase가 테이블 join 결과를 추론할 때 FK 관계가 1:N이면 무조건 배열로 추론하기 때문이에요.Supabase가 테이블 join 결과를 추론할 때 FK 관계가 1:N이면 무조건 배열로 추론하기 때문이에요.
  실제로는 order_items 하나에 products 하나가 연결되는 1:1 관계인데, DB에 unique constraint가 없으면 Supabase 입장에서는 "여러 개일 수도 있다"고 판단해서 배열 타입으로 추론해요.
  그래서 실제 데이터는 객체로 오는데 TypeScript 타입은 배열로 잡혀서 불일치가 생긴 거예요.

### 😵 어려웠던 점

- 데이터를 연결하여서 깊숙한 컴포넌트까지 연결이 되어야 하니깐, 에러 메시지가 나와도 어느 지점인지 알 수가 없었다. 영어로 오류가 나오는데 봐도 이해가 안되고, 몇 시간을 이 문제를 두고 여기저기 해보고, 코드 구조를 바꾸고 했는데도 문제가 해결이 되지 않았다. 컴포넌트 코드 구조가 문제가 아닌 데이터를 받아오는 과정에서 내가 원하는 것은 상품이 객체 하나인데, 배열로 여러개의 상품을 보내주고 있었다. 이럴 경우에는 무조건 데이터 반환을 할때 타입을 알려주거나, supabase에서 자동으로 타입을 정해주는 기능이 있다고 하는데 팀 프로젝트다 보니깐 마음대로 설치할 수 없어서 그래서 데이터를 불러오는 함수에서 반환값에 명확하게 원하는 타입을 지정해준 후에는 데이터가 잘 불러져왔다. 타입스크립트 내가 원하는대로 타입을 조립할 수 있어서 좋지만, 꼼꼼해야 하고 타입을 어떻게 응용해주느냐가 문제 인 것 같다. 언제쯤 익숙해질려나...! 익숙해지고 싶다!
